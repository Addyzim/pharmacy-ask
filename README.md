# Pharmacy Ask — вопросы к данным аптечной сети

Демо системы «вопрос → SQL → ответ». Пользователь пишет вопрос на русском,
модель строит SQL к витрине, сервер выполняет его **только на чтение**, а интерфейс
показывает ответ, график, таблицу, формулу расчёта и источник каждой цифры.

```
вопрос → Claude (SQL + тип графика + формула) → SQLite (read-only) → таблица + Chart.js
                                                        ↓
                            проверка: все числа в тексте сверяются с результатом запроса
```

## Запуск лаунчером (проще всего)

Двойной клик по **`Pharmacy Ask.bat`** — откроется окно лаунчера: статус сервиса,
поле для ключа Claude API, кнопки «Запустить / Остановить / Открыть в браузере».
При первом запуске витрина собирается из Excel автоматически, браузер открывается сам.
Порт подбирается свободный, начиная с 8077.

## Онлайн-версия (GitHub Pages)

<https://addyzim.github.io/pharmacy-ask/> — та же система целиком в браузере:
витрина SQLite грузится через sql.js, SQL выполняется на стороне клиента, сервер не нужен.
Без ключа работают 24 готовых вопроса; ключ Claude API вводится кнопкой «Ключ API»
и хранится только в localStorage браузера.

Пересобрать статическую версию: `python build_static.py` (складывает всё в `docs/`).

## Быстрый старт (Windows)

```powershell
pip install -r requirements.txt
python etl.py                      # Excel -> pharmacy.db + sql/*.sql (нужен один раз)
$env:ANTHROPIC_API_KEY = "sk-ant-..."   # без ключа поднимется демо-режим
python -m uvicorn app:app --port 8077
```

Открыть <http://127.0.0.1:8077> → логин **admin** / **admin**.

## Режимы

| Режим | Когда | Что делает |
|---|---|---|
| LLM | задан `ANTHROPIC_API_KEY` | любой вопрос: модель пишет SQL и комментирует результат |
| Демо | ключа нет | 24 готовых вопроса с заранее написанным SQL — работает офлайн |

Демо-режим страхует презентацию: даже без интернета кнопки-подсказки отвечают.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | ключ Claude API |
| `PHARMACY_MODEL` | `claude-sonnet-5` | модель |
| `PHARMACY_USERS` | `admin:admin` | логины через запятую: `user1:pass1,user2:pass2` |
| `PHARMACY_SECRET` | `pharmacy-demo-secret` | соль для подписи сессионной cookie |

## Ограничения системы (заявлены пользователю в интерфейсе)

1. **Честность вместо выдумки.** Если данных для ответа нет, модель обязана вернуть
   `answerable: false` с объяснением, а не подменять вопрос похожим.
   Пустой результат запроса тоже показывается честно.
2. **Только чтение.** База открыта как `file:pharmacy.db?mode=ro`, плюс два рубежа:
   регулярка `guard()` (только `SELECT`/`WITH`, один запрос, без `;`) и
   `sqlite3.set_authorizer` — SQLite сам отклоняет всё, кроме `SELECT`/`READ`/`FUNCTION`.
3. **Защита от инъекций.** Текст вопроса передаётся модели в теге `<question>` как данные,
   а не как инструкции; попытки «забудь правила», многозапросные конструкции и команды
   на изменение данных отклоняются на уровне SQL-гарда. Длина вопроса ограничена 500 символами.
4. **Проверка чисел.** `verify.py` вытаскивает все числа из текста ответа и сверяет их
   со значениями результата (включая суммы, доли, разницы). Несверенное число подсвечивается
   предупреждением прямо под ответом.
5. **Провенанс.** Под каждым ответом: формула метрики, список таблиц с числом строк,
   исходный Excel-файл (скачивается по ссылке) и система-источник, плюс сам SQL-запрос.

## Выгрузки

* Под каждым ответом — кнопки **Excel**, **CSV** и **Слайд**.
* Excel: лист «Данные» с результатом запроса и лист «Как посчитано» — вопрос, формула, SQL и источники.
* CSV: разделитель `;` и BOM, открывается в русском Excel без плясок с кодировкой.
* Слайд: PowerPoint 16:9 с графиком, выводом и сноской «чем посчитано» — можно вставлять в отчёт.
* Исходные Excel-выгрузки и SQL-дампы скачиваются из окна «Источники данных».

## Источники данных

13 таблиц собраны из 12 выгрузок (1С, ККМ, интернет-магазин). Данные синтетические:
8 аптек, 20 SKU, июнь 2026, суммы в UZS.

| Таблица | Что внутри | Файл |
|---|---|---|
| `sales_weekly` | продажи по позициям (350) | SalesWeekly.XLSX |
| `check_lines` | строки чеков: продавец, себестоимость, пол покупателя (517) | CheckUASNew.XLSX |
| `cheques` | шапки чеков (400) | ChequesWeeklyNew.XLSX |
| `stock` | остатки по дням (827) | Stock.XLSX |
| `movements` | движение по сериям, цены, сроки годности (360) | Движения товаров… .xlsx |
| `sales_4m` | продажи за 4 месяца с поставщиком (220) | Продажи 4 мес справочник.xlsx |
| `sales_online` | онлайн-заказы (160) | SalesOnline.XLSX |
| `so_days` | остатки на дату среза (118) | SO days.xlsx |
| `refusals` | отказы / дефектура (90) | Refusals.XLSX |
| `arrivals` | приходы от поставщиков (70) | Arrivals.XLSX |
| `products` | справочник номенклатуры (20) | Справочник номенклатур.xlsx |
| `stores` | справочник аптек и районов (8) | Цель на Мес.xlsx |
| `targets` | планы месяца и недели (8) | Цель на Мес.xlsx |

Выгрузки доступны из интерфейса (кнопка «Источники данных») и в репозитории:

* `data/*.xlsx` — исходные Excel-файлы
* `sql/schema.sql` — DDL витрины
* `sql/pharmacy_dump.sql` — полный дамп данных
* `pharmacy.db` — готовая база SQLite

## Примеры вопросов

* Выручка по аптекам за месяц
* Какая аптека хуже всех выполняет недельный план
* Средний чек и глубина чека по аптекам
* На сколько дней хватит остатков (SO days)
* Что скоро истекает по сроку годности
* Сколько теряем на скидках

## Структура

```
app.py             FastAPI: авторизация, /api/ask, выгрузки, гард SQL
etl.py             Excel -> SQLite + экспорт sql/
schema.py          схема витрины и бизнес-глоссарий для промпта
provenance.py      таблица -> исходный файл, формулы метрик
verify.py          сверка чисел из ответа с результатом запроса
demo_questions.py  готовые вопросы (офлайн-режим и подсказки)
demo_extra.py      дополнительные готовые вопросы
static/index.html  интерфейс (Inter, Chart.js, дизайн-токены дашбордов)
static/login.html  страница входа
launcher.pyw       лаунчер с графическим интерфейсом
build_static.py    сборка браузерной версии в docs/ для GitHub Pages
docs/              статическая версия: sql.js + витрина + выгрузки
```

## Деплой

```bash
docker build -t pharmacy-ask .
docker run -p 8077:8077 -e ANTHROPIC_API_KEY=sk-ant-... pharmacy-ask
```

Порт задаётся переменной `PORT` (по умолчанию 8077).

Демо для презентации: авторизация простая (cookie с HMAC-подписью), данные синтетические.
